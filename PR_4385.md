Closes #4385

## What changed

- Added optional `token_budget` and `cost_budget_usd` run limits to `run_workflow`, the workflow settings (`workflow-token-budget`, `workflow-cost-budget-usd`) and the run record. Limits are lowered-only: a call can tighten but never raise a configured budget.
- Before a new worker starts, the run re-reads its workers' turns from the data store through a small `threads_usage()` reader (tokens and only harness-reported USD). When a limit is reached, further `agent()` calls are refused with `the run reached its token budget` or `the run reached its cost budget of $X.XX`. Workers already running are not interrupted.
- `workflow_status` always includes `usage: { tokens, cost_usd, cost_reported_by: "n/m workers", workers }` and `limit_hit`, with or without budgets configured; the app's run summary uses the same fields.
- Added unit tests with a temporary data store / injectable usage reader covering all acceptance criteria: token budget stops new workers, cost budget counts only reported USD and reports how many workers reported none, running workers finish, lowered-only limits, and status usage output. `docs/workflows.md` and `docs/configuration.md` updated.
